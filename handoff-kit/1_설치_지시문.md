# 1. 설치 지시문 — 프로젝트 폴더에 인계 체계 만들기

**언제:** 어떤 프로젝트든 처음 한 번. 그 프로젝트 폴더를 연 에이전트에게 아래 상자 전체를 복사해 붙여넣습니다.
**어디서든:** Claude Code, Codex, Cursor, Gemini CLI 등 파일을 읽고 쓸 수 있는 에이전트면 됩니다.
**기존에 긴 기록 문서(백서 등)가 있으면** 이 지시문 대신 `4_기존백서_이전_지시문.md`를 쓰세요.

~~~~text
[인계 체계 설치 요청]

목적: 내가 한도에 걸리거나 계정·플랫폼을 바꿔도, 다른 에이전트가 이 폴더를 열자마자
따로 설명 없이 "지금 어디까지 왔고 다음에 무엇을 할지" 알 수 있게 만드는 것.

먼저 이 프로젝트 폴더 전체를 훑어보고(코드·문서·git 기록), 아래 파일을 만들어줘.
내용은 네가 폴더에서 확인한 사실로 채우고, 모르는 것은 지어내지 말고 "확인 필요"라고 적어.

■ 만들 파일
1) AGENTS.md (프로젝트 맨 위 폴더) — 모든 에이전트가 가장 먼저 읽는 안내서
2) CLAUDE.md — 한 줄만: "@AGENTS.md 를 먼저 읽고 그대로 따른다."
   (이미 CLAUDE.md가 있으면 그 내용은 AGENTS.md로 옮기고 같은 한 줄로 바꿔줘)
3) GEMINI.md — CLAUDE.md와 같은 한 줄
4) docs/handoff/00_현황판.md   — 최대 40줄. 새 에이전트는 이것만 읽고 시작한다.
5) docs/handoff/01_결정기록.md — 내가 결정한 것과 그 이유
6) docs/handoff/02_알아낸것.md — 작업하며 확인한 사실(원인, 수치, 함정)
7) docs/handoff/log/YYYY-MM.md — 경과 로그. 월별 파일.

■ AGENTS.md 구성 (최대 80줄)
- 프로젝트 한 줄 설명, 목표
- 폴더 구조 요약 (중요 폴더만)
- 실행·테스트·빌드 방법 (실제 명령어)
- 작업 시작 순서:
  1. git pull 로 최신 상태 받기
  2. docs/handoff/00_현황판.md 읽기 (다른 handoff 파일은 필요할 때만)
  3. 작업 전에 사용자에게 5줄 이내로 "이해한 현재 상태 + 이번에 할 일" 확인받기
- 기록 규칙 (아래 ■ 기록 규칙을 그대로 옮겨 적기)
- 절대 하지 말 것 (프로젝트 특성에 맞게: 예. 실거래 키 사용, 운영 DB 삭제, 비밀정보 커밋)
- 참고 자료 위치 (다른 문서·외부 링크)
- 사용자 호칭과 말투: 쉬운 한국어, 전문용어는 풀어서, 질문에는 먼저 답하고 보고는 끝에 짧게

■ 00_현황판.md 양식 (최대 40줄, 매번 "덮어쓰기"로 갱신)
  # 현황판
  마지막 갱신: YYYY-MM-DD HH:MM / 작업한 곳(예: Claude 계정A, Codex) / 마지막 커밋 해시
  ## 한 줄 요약
  ## 지금 위치 (무엇을 하던 중인지, 어디서 멈췄는지 — 파일·함수 이름까지)
  ## 다음 할 일 (우선순위 순 최대 3개, 각 1줄)
  ## 사용자 답을 기다리는 질문 (번호, 각 1줄)
  ## 위험·주의 (지금 깨져 있거나 조심해야 할 것)
  ## 최근 바뀐 것 (작업일마다 3줄 이내, 7일 지난 항목은 log로 내림)
  - MM-DD: ...

■ 01_결정기록.md 양식
  | 번호 | 날짜 | 결정 | 이유 | 사용자 원문(한 줄) |
  번호는 D-01부터. 뒤집힌 결정은 지우지 말고 "→ D-xx로 변경" 표시.

■ 02_알아낸것.md 양식
  주제별 소제목 아래 "- 사실 (근거: 파일/명령/날짜)" 형식. 틀린 것으로 밝혀지면 고쳐 쓴다.

■ log/YYYY-MM.md 양식
  - MM-DD HH:MM | 요청 요지 | 한 일 | 결과   ← 한 줄 150자 이내

■ 기록 규칙
- 현황판은 매 턴이 아니라 "의미 있는 진전·결정·막힘이 생겼을 때"와 "작업을 끝낼 때" 갱신한다.
- 로그는 작업 단위(요청 하나)마다 한 줄. 대화 원문을 길게 옮기지 않는다.
- 결정은 사용자가 확정한 것만 01_결정기록에 적는다. 내 제안은 현황판 "질문"에 둔다.
- 기록을 고친 뒤에는 git commit + push 까지 한다. 다른 계정·플랫폼은 GitHub에서 이어받는다.
- 사용자가 "인계 준비" 또는 "한도 임박"이라고 하면 하던 일을 멈추고 즉시 현황판을 갱신·push한다.
- 비밀번호, API 키, 개인정보는 어떤 기록 파일에도 적지 않는다.
- 자동 검사(훅)로 매 턴 기록을 강제하지 않는다. (훅은 Claude 전용이라 다른 플랫폼에서는 작동하지 않고, 사용량만 늘린다)

■ 마무리
1. .gitignore 에 .env, 키 파일, node_modules, build 등이 빠져 있으면 추가해줘.
2. 만든 파일을 commit 하고 push 해줘. (원격 저장소가 없으면 알려줘)
3. 끝나면 나에게 아래만 보고해:
   - 만든 파일 목록
   - 현황판 내용 그대로
   - "확인 필요"로 남긴 항목
~~~~
