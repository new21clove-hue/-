# 4. 기존 백서 이전 지시문 — 이미 긴 기록 문서가 있는 프로젝트

**언제:** 매매 봇 프로젝트처럼 `docs/00_프로젝트기록.md` 같은 큰 문서(0~8장, 100KB 이상)가 이미 있을 때, `1_설치_지시문` 대신 이것을 씁니다.
**원칙:** 내용은 하나도 버리지 않고 **나누기만** 합니다. 원본은 보관용으로 남깁니다.

~~~~text
[기존 기록 문서를 인계 체계로 나누기]

이 프로젝트에는 docs/00_프로젝트기록.md (0~8장, 한 파일)가 있다. 너무 길어서
새 에이전트가 매번 전부 읽어야 하는 문제가 있다. 내용을 버리지 말고 아래처럼 나눠줘.

■ 장별 옮길 곳
- 0장 읽는 법·갱신 규칙   → AGENTS.md "기록 규칙" (아래 새 규칙으로 교체)
- 1장 지금 상태           → docs/handoff/00_현황판.md (요약해서 40줄 이내)
  1-2 지금까지 알아낸 것  → docs/handoff/02_알아낸것.md
- 2장 목적·범위           → AGENTS.md 맨 앞 "프로젝트 설명"
- 3장 결정 기록 D-01~     → docs/handoff/01_결정기록.md (번호·원문 그대로)
- 4장 기획안              → docs/기획안.md (그대로 옮김)
- 5장 열린 질문           → 현황판 "사용자 답을 기다리는 질문" (최대 5개, 나머지는 01_결정기록 아래 "보류 질문")
- 6장 경과 로그           → docs/handoff/log/YYYY-MM.md (월별로 나눔, 내용은 그대로)
- 7장 근거 자료           → AGENTS.md "참고 자료 위치"
- 8장 인계 메모           → AGENTS.md "절대 하지 말 것" + 현황판 "위험·주의"
- 원본 파일              → docs/archive/00_프로젝트기록_원본.md 로 이동 (수정 금지)

■ 새 구조와 양식
handoff-kit/1_설치_지시문.md 의 "만들 파일", "양식", "기록 규칙"을 그대로 따른다.
(그 파일이 이 폴더에 없으면, 내가 따로 붙여줄 테니 요청해)

■ 자동 검사(훅) 정리
- .claude/settings.json 등에 "매 턴 기록 갱신을 강제"하는 훅이 있으면 끄거나 지워줘.
- 지우기 전에 어떤 훅이 무엇을 하는지 나에게 먼저 보여줘.

■ 마무리
1. 옮기기 전후로 빠진 내용이 없는지 장별로 대조해서 확인해줘.
2. commit + push.
3. 나에게 보고: 새 파일 목록, 현황판 전문, 지운/끈 훅 목록, 대조 결과.
~~~~
